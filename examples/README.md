# 示例项目导览：monograph-writing 全流程 demo

这是一个**完整走通全流程的最小示例项目**《学术写作方法论（示例）》——演示从项目初始化、按三段式写小节、批次校验，到生成纯正文版的全套产物。浏览完本导览约需 5 分钟，即可理解技能的产出长什么样。

> 注意：示例为保持可读性将字数档缩小为 小节 120~200 字／节级总结 80~150 字／章末小结 60~120 字（真实项目默认档为 1500~2000／600~800／300~500，见 `demo-project/00_管理文件/书稿配置.json`——改这一个文件即可调整）。

## 1. 项目长什么样

```
demo-project/
├── 00_管理文件/
│   ├── 专著目录.md          ← 全书结构的唯一依据（第二章仅存骨架，演示"待并入"行为）
│   └── 书稿配置.json        ← 字数分级等全部参数
├── 01_书稿/第一章 学术写作的基本原理/
│   ├── 1.1 写作即研究/
│   │   ├── 1.1.1 写作与研究的关系.md          ← 旗舰样例：三段式最完整
│   │   ├── 1.1.2 读者的角色.md
│   │   └── 第一章 1.1节 写作即研究 章节总结.md  ← 节级总结（每批最后产出）
│   ├── 1.2 批次化推进/（同构，含 表1-1、表1-2）
│   └── 1.3 小结.md                            ← 章末小结（只依据各节级总结撰写）
├── 02_语料/                  ← 你的文献库（格式不限；本示例留空）
├── 03_归档素材/              ← 外部旧稿（走修复流程，不直接采用）
└── 04_剥离版书稿/            ← 脚本生成的纯正文版（含每章合并稿）
```

## 2. 一个小节文件的内部（三段式）

打开 [1.1.1 写作与研究的关系](demo-project/01_书稿/第一章%20学术写作的基本原理/1.1%20写作即研究/1.1.1%20写作与研究的关系.md)，你会看到固定三段：

```markdown
# 1.1.1 写作与研究的关系
> （文档定位说明）
## 一、写作准备        ← 论点树＋证据清单＋提纲（成书时剥离；审稿时可溯源）
## 二、正文            ← 加粗观点句领起的正文；引用 [n] 按首现顺序编号
## 参考文献            ← GB/T 7714 著录，编号与正文一一对应
```

**关键细节**：证据清单表格里每条论据都挂来源文献；正文引用编号从 [1] 连续递增——这些正是校验脚本逐项检查的对象。

## 3. 初始化的输出

对 AI 助手说"用 monograph-writing 初始化我的专著项目，目录在 xxx.md"后，`init_project.py` 会打印：

```
[初始化完成] 项目：/path/to/your-book
  书名：《学术写作方法论（示例）》｜章：2｜小节：6｜章末小结指令：2
  生成文件：00_管理文件/ 下 书稿配置.json、写作进度台账.md、
  术语与符号一致性台账.md、写作指令清单.md
```

并生成全部骨架目录（含 `02_语料/把文献放这里.md` 使用说明）。

## 4. 批次收尾：校验脚本的输出

每个批次（一个二级目录）写完，AI 助手必跑校验。示例项目的真实输出：

```
$ python3 scripts/validate_manuscript.py --root examples/demo-project

[OK   ] 1.1.1 写作与研究的关系.md (小节)，字数 182，引用 2 条
[OK   ] 1.1.2 读者的角色.md (小节)，字数 200，引用 2 条
[OK   ] 第一章 1.1节 写作即研究 章节总结.md (节级总结)，字数 138，引用 3 条
[OK   ] 1.2.1 把大任务拆成批次.md (小节)，字数 200，引用 1 条
[OK   ] 1.2.2 批次的收尾检查.md (小节)，字数 179，引用 2 条
[OK   ] 第一章 1.2节 批次化推进 章节总结.md (节级总结)，字数 141，引用 2 条
[OK   ] 1.3 小结.md (章末小结)，字数 100，引用 2 条

== 汇总：OK 7 个文件，ERROR 0 项，WARN 0 项，豁免 0 个 ==
全部通过 ✅
```

**当出现问题时**（例如把 1.1.1 正文的引用顺序对调成先 [2] 后 [1]）：

```
[ERROR] 1.1.1 写作与研究的关系.md (小节)
    - 引用编号非按首次出现顺序递增（首个乱序号: [1]）
== 汇总：… ERROR 1 项 … ==
存在 ERROR：请修复后复跑本脚本，直到 ERROR 清零再收批。
```

错误清零，批次才算收尾。

## 5. 成书输出：剥离版

[04_剥离版书稿/](demo-project/04_剥离版书稿/) 内是脚本自动剥离"写作准备"后的纯正文版：

- **逐篇镜像**：与 01_书稿 同构，1:1 可溯源（对比 [原稿](demo-project/01_书稿/第一章%20学术写作的基本原理/1.1%20写作即研究/1.1.1%20写作与研究的关系.md)与[剥离版](demo-project/04_剥离版书稿/第一章%20学术写作的基本原理/1.1%20写作即研究/1.1.1%20写作与研究的关系.md)——只剩标题、正文、参考文献，一字未改）；
- **章合并稿**：[第一章 学术写作的基本原理.md](demo-project/04_剥离版书稿/第一章%20学术写作的基本原理.md)，可直接整章复制进 Word；
- 再跑 `merge_to_word.py` 即得带目录域与排版样式的单个 .docx（本仓库的 [Release 附件](https://github.com/newdeme/monograph-writing/releases) 提供了示例生成的合并稿，可直接下载查看效果）。

## 6. 修改示例后如何再生成

```bash
python3 examples/make_demo.py   # 复跑校验＋剥离版生成
```

## 7. 换成你自己的书（3 步）

1. 把 `demo-project/00_管理文件/专著目录.md` 换成你的目录（章-节-小节三级）；
2. 对 AI 助手说："用 monograph-writing 技能初始化我的专著项目，目录在 xxx.md"；
3. 之后每次说"**继续**"——它会按台账推进下一批次，每批收尾给你一份汇报。

完整方法论见仓库 [`SKILL.md`](../SKILL.md) 与 [`references/`](../references/)。

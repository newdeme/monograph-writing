# 批次工作流细则与常见坑

> SKILL.md §3 的展开。末节"常见坑清单"来自真实专著 200+ 小节写作批次沉淀的教训，动笔前值得通读一遍。

## 1. 批次启动核对单

- [ ] 读台账 §2：确认下一批次、有无 A/B 选项待作者点单、有无跨会话断点
- [ ] 读《专著目录.md》与《写作指令清单.md》：定位批次范围
- [ ] 查术语台账：本节涉及术语是否已登记、拟用符号有无冲突
- [ ] 查台账 §3：本章表/图编号指针（下一个表号/图号）
- [ ] 查台账 §4：拟引文献是否已在核实缓存中
- [ ] 一句话向作者确认范围后开工

## 2. 三步法执行细则

### 论点树（第一步的核心）
- 核心论点必须是**可论证的判断句**，不是话题词。差："介绍 XX 方法"；好："XX 方法在 YY 条件下优于 ZZ，原因有三"。
- 每条分论点后括注对应证据编号，证据清单表格里能找到——论点与证据一一挂钩，写作时不许出现"无证据支撑的分论点"。
- 落脚点必须写**衔接**：本节结论如何被下一小节/下一章使用。这是防止章节写成孤岛的关键。

### 证据检索
- 每小节用 2~4 组关键词检索，中外文都要试；数据类论据（装机量、占比、参数）优先用带数值的检索词。
- 检索结果先筛题录（标题/年份/来源），拟引用的**逐条读原文核对**后再进证据清单。
- 证据不够时：①换关键词再检；②确认确实缺据后，在正文标注"此处需补充文献支撑"并登记台账 §5，**绝不编一条来凑**。

### 正文写作
- 开篇定位段（2~3 句）：本节在全节/全章中的位置与要解决的问题。
- 每段以**加粗观点句**领起，段内展开论证——观点句让作者快速审读，也让全书逻辑骨架可见。
- 收束段：本节结论＋一句衔接下一小节。
- 转述文献（A 引 B 而你只见 A）在条目内标注"（转述）"；出版年不详标"[出版年不详]（出版信息待作者终核）"。

### 字数口径
- 统计的是**叙述文字**（中文字符逐字计、连续西文/数字串计 1），不含表格行、写作准备、参考文献——校验脚本与此口径一致，以脚本实测为准。
- 压不进区间：先删修饰语 → 再合并同类论据 → 最后与作者商量调档。不为凑字注水，不为达标砍论据。

## 3. 引用编号规则（最高发错误，重点掌握）

- [n] 按**含表格的阅读顺序**首次出现排列：表内引文先于正文出现时，按表格位置计序。
- 参考文献列表编号连续（1..N），条目数＝正文最大引用号。
- 同一文献在同一文件内**不得重复编号**（节级总结重编号时同样适用）。
- 节级总结的文献表：仅限本节各小节已引文献，去重后**按总结正文出现顺序重新编号**——不是照抄小节里的编号。
- GB/T 7714 类型标识：[J] 期刊 / [M] 专著 / [C] 会议录 / [R] 报告 / [D] 学位论文 / [S] 标准 / [EB/OL] 电子资源等，缺失是 WARN。

## 4. 节级总结与章末小结

| | 节级总结 | 章末小结 |
|---|---|---|
| 触发 | 每个二级目录批次内最后产出 | "X.Y 小结"指令，单独成批 |
| 依据 | 本节各小节正文 | **只依据该章各节级总结**（防上下文遗忘） |
| 字数 | 600~800（或配置） | 300~500（或配置） |
| 结构 | 逐小节归纳 → 本节逻辑主线 → 衔接下一节 | 本章核心结论 → 衔接下一章 |
| 文献 | 本节已引文献去重重编号 | 各节级总结文献汇总去重重编号 |
| 后续动作 | — | 触发本章人工检查点（符号/衔接/台账 §5 清零） |

## 5. 批次收尾四件事执行标准

1. **校验**：`python3 <技能路径>/scripts/validate_manuscript.py`（在项目根目录运行）。ERROR 逐条修复复跑至清零；WARN 判断：可接受 → 台账 §6 记录＋理由；不可接受 → 修复。
2. **台账更新**：§2 完成清单（文件名＋实测字数＋引用数＋日期＋✅）、§3 指针前移、§4 新核实书目（附定稿著录串，供后续批次直接复用）。
3. **汇报**：文件清单、脚本汇总行（受检 N 文件 ERROR 0 WARN M）、遗留 WARN 处理、下一批次预告。
4. **自查**：声称清单↔工具回执一一对应后才发汇报。

## 6. 常见坑清单（历史真实教训）

1. **引用首现顺序错**：最常见 ERROR。表格里的 [n] 也计入阅读序。每批收尾自查一遍。
2. **字数口径误解**：以为要算表格行——不算；以为写作准备也计——不计。以脚本为准。
3. **全书统一替换项**：繁体字混入（如"停產"）、英文单词残留（如"therefore"）、全角连接号"－"应为半角"-"。收尾时用全文搜索扫一遍。
4. **归纳表挂文献名**：自己归纳的框架表必须在标题处标"本节归纳"，不得让读者误以为出自某文献；反之，文献数据表须逐格可溯。
5. **合订本 PDF 引用**：多篇文章合订的 PDF 必须定位到具体文章（作者、篇名、页码），不得整本当一条文献引。
6. **节级总结引入新文献**：总结只能汇集小节已引文献，出现新文献即违规。
7. **改历史章节**：发现已完成章节与新裁决矛盾时只登记台账 §5，**不得悄悄改写**——成稿修订批统一处理。
8. **文件名漂移**：与目录逐字一致是硬规则，多个空格、全半角差异都会导致合并脚本定位失败。
9. **文件夹命名**：章/节文件夹名同样与目录逐字一致；文件名保留完整编号前缀，不因入夹缩短。
10. **跳批写作**：不跳节不跳章；作者点单例外（副线批次），但须在台账 §2 标注"作者点单"。
11. **虚构数据**：作者科研数据未到位时以"需作者补充"占位，绝不用"合理估计"补数。
12. **概念写成结论**：概念性设想/展望必须用"设想/展望/有待验证"语态，不得写成已完成的工程验证结论。

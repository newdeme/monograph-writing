# 修复批次：整合外部草稿

> 外部草稿＝作者旧稿、合作者手稿、其他工具生成的文本。这类材料**结构不合规、书目不可信**是常态，必须走修复批次，不得直接当书稿用。

## 1. 为什么必须修复

真实教训：一部专著曾接收 18 个外部提供文件，校核发现其中含**虚构/失真书目**（不存在的卷期页码、错配的作者与文章）与不可溯源数据。直接采用等于把错误埋进成书。修复批次的花费远低于成书后返工。

## 2. 修复流程（五步）

### 第一步：校核报告
逐文件核对，产出《校核报告_外部草稿_批次名.md》，每文件给出分类：

- **A 修正后保留**：骨架可用、书目基本可核——列具体问题清单（哪条引用错、哪段无据）。
- **B 含必须舍弃的内容**：虚构/失真书目、不可溯源数据、与他人成果疑似雷同的段落——逐条指明位置与舍弃理由。
- **C 整体重写**：结构不合规且内容价值低。

### 第二步：作者裁定
报告提交作者，确认分类与修复口径；争议项登记台账 §5。

### 第三步：豁免登记
待修复文件加入配置 `exempt_patterns`（校验脚本期间跳过，不计入 ERROR 统计——避免修复期噪音淹没正常批次的校验信号）。

### 第四步：逐文件修复（取材纪律）
- **只取骨架与语料内可溯论据，逐句重写**——外部草稿的句子不得整段挪用。
- 虚构/失真书目：语料内核实到可替代文献则替换；核不到则删，正文标"需补充文献支撑"。
- 结构改造为标准三段式；脚注式引用改 [n] 编号制；字数压进分级区间。
- 表/图编号按**全章**统一重排（不只改本文件），重排后更新台账 §3 指针，并检查已完成小节的编号是否受影响（受影响时登记台账 §5，成稿修订批统一处理，不悄悄改）。

### 第五步：验收
1. 从 `exempt_patterns` 移出对应文件；
2. 全量复跑校验脚本至 ERROR 清零；
3. 台账 §2 计入定稿进度（注明"修复批次"）；
4. 校核报告归档进 `00_管理文件/`，作为教训档案。

## 3. 校核报告模板

```markdown
# 校核报告：外部草稿（X.Y 节批次）

> 校核日期：YYYY-MM-DD ｜ 校核范围：N 个文件 ｜ 结论：A 保留 n1 / B 舍弃内容 n2 / C 重写 n3

## 逐文件结论

### 文件名 1 —— A 修正后保留
- 问题 1：引用 [3] 书目与原文不符（原：…；实际：…）→ 处理：替换为语料内 XXX
- 问题 2：第 2 段数据无来源 → 处理：标注"需作者核实"

### 文件名 2 —— B 含必须舍弃内容
- 舍弃 1：引用 [1][5][7] 为虚构书目（查无此文）→ 处理：删除，论点改挂语料内文献
- …

## 共性问题与修复口径
- （如：全部文件需脚注改编号制；表编号全章重排）

## 待作者裁定
- （登记台账 §5 的条目）
```

## 4. 预防优于修复

新收外部材料时先问三个问题：①来源是否可靠（作者本人旧稿 vs 不明出处的文本）；②书目是否可核；③是否需要与现有章节去重。答案不利时直接按修复批次处理，不要抱侥幸心理直接采用。

# 项目初始化指南（访谈 · 配置 · 语料适配）

> SKILL.md 入口 A 的展开。初始化质量决定全书几百个批次是否顺畅——多花 30 分钟把目录和配置定准，胜过中途返工。

## 1. 初始化访谈清单（逐项与作者确认，缺一不可）

1. **书名与学科定位**：正式书名；读者对象（研究生/学者/工程师）；有无出版社格式要求。
2. **全书目录**：章（一级）→ 节（二级）→ 小节（三级）三级结构。作者给不出完整目录时协助梳理，**作者明确批准后冻结**为 `00_管理文件/专著目录.md`。冻结前提醒作者：目录是全书结构与文件命名的唯一依据，冻结后改动须作者确认并升版。
3. **字数分级**：各章小节目标字数（常见分法：核心章 1500~2000 字、概述章 900~1200 字）、节级总结（600~800）、章末小结（300~500）。有没有"特色节写足写厚"的豁免需求（如某节作者明确说不受字数限制）——豁免档写入配置 `special_tiers`，并把裁定记录在台账 §5。
4. **引用格式**：默认 GB/T 7714 顺序编码制（[n] 按首现顺序）；也可配 APA 等其他格式——注意校验脚本的"文献类型标识检查"只适配 GB/T 7714，用其他格式时在配置中把 `check_citation_style` 设为 false。
5. **文献语料**（红线第 2 条的落地）：走"语料接入访谈"四选一——① AI 客户端知识库 / ② Zotero 等文献管理器 / ③ 项目内 `02_语料/` 文件夹（格式不限，作者自行补充） / ④ 暂不接入（降级模式）。选定后按台账 §1 结构化格式登记；选型对比与从零搭建见 `references/evidence-corpus.md`。
6. **图表编号与命名规则**：默认 `表X-Y`/`图X-Y`、文件名分隔符用空格、三段式文件结构——除非作者另有要求，否则按默认执行并登记台账 §1。
7. **符号体系锚点**：全书统一符号在哪个小节立法确立（如"3.1.5 坐标系与符号体系"）？没有的话建议在最早的计算理论章设一个，登记术语台账 §2。

## 2. 《书稿配置.json》逐项说明

```jsonc
{
  "book_title": "书名（不含书名号）",
  "author": "作者名（可选）",
  "citation_style": "GB/T 7714（顺序编码制）",
  "catalog_file": "00_管理文件/专著目录.md",
  "manuscript_dir": "01_书稿",
  "stripped_dir": "04_剥离版书稿",
  "excluded_dirs": ["00_管理文件", "03_归档素材", "04_剥离版书稿", ".claude", ".git"],
  "word_targets": {
    "default": [1500, 2000],
    "by_chapter": { "1": [900, 1200], "2": [900, 1200] },
    "section_summary": [600, 800],
    "chapter_summary": [300, 500]
  },
  "special_tiers": [
    { "pattern": "^9\\.4\\.\\d+ ", "target": [1400, 2600], "reason": "特色节豁免，2026-01-01 作者裁定" }
  ],
  "exempt_patterns": [],
  "tolerance": 0.15,
  "check_citation_style": true
}
```

| 字段 | 说明 |
|---|---|
| `word_targets.default` | 未在 `by_chapter` 列出的章的小节字数区间 |
| `word_targets.by_chapter` | 按章号覆盖小节字数区间（键为章号字符串） |
| `special_tiers` | 按文件名正则匹配的特殊字数档（特色节豁免等）；**按数组顺序取首个命中**，窄档（如 `^12.4.5 `）要排在宽档（`^12.4.\d+ `）之前 |
| `exempt_patterns` | 完全跳过校验的文件名正则列表（待修复外部文件），修复完成后移出 |
| `tolerance` | 区间外 ±15% 为 WARN，再往外为 ERROR（此比例即该值 0.15） |
| `check_citation_style` | 是否检查参考文献含 GB/T 7714 类型标识（[J]/[M]/[C] 等，WARN 级） |

改配置后复跑 `validate_manuscript.py` 验证生效。**配置属于"已确认的全局决策"，改动须作者同意并记录台账 §5。**

## 3. 文献语料接入（四方式）

红线只要求"证据可溯源、题录可核对"，不绑定具体工具。初始化访谈四选一并登记台账 §1：

| 方式 | 一句话说明 | 检索/核对 |
|---|---|---|
| ① AI 客户端知识库 | 语义检索最强；在所用 AI 助手内建库上传文献 | AI 用知识库搜索 2~4 组关键词；读原文工具核对首页题录与页码 |
| ② Zotero 等文献管理器 | 已在用文献管理软件的研究者零成本 | 条目检索＋附件抽读；题录仍须抽对一次原文 |
| ③ 项目内 `02_语料/` 文件夹 | 任何用户的最简起点：初始化自动创建，文献拖进去即可 | AI 定位并直接读文件；书目从文献首页誊录 |
| ④ 暂不接入（降级模式） | 文献未齐、先写骨架 | 只可引用作者手工核实过的文献与台账 §4 缓存 |

`02_语料/` 文件夹**格式不限**：PDF、Word、Excel、Markdown、TXT 等均可（放什么由作者决定），内附《把文献放这里.md》使用说明。四方式的从零搭建步骤、中途升级切换、语料质量建议见 `references/evidence-corpus.md`。

## 4. 初始化后第一天

1. 向作者展示生成的目录结构、配置、双台账，逐项确认；
2. 确认第一批次范围（通常 1.1）；
3. 按三步法写第一个小节，写完立即跑一次校验脚本——让作者尽早看到校验机制，建立信任；
4. 第一个批次收尾后，把踩到的坑沉淀进台账 §6，流程问题反馈进本技能的改进记录。

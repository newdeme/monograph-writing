# 独立核验批次（干净会话核验模式 · 引用语义错配核验 · 核验任务书）

> 写作与核验分离：写作者不自证。本文件定义「独立核验批次」——用一个**没有写作上下文的干净会话**，按核验任务书对已完成章节做独立复查，重点覆盖机器校验管不到的语义层（引用是否真的支持论断）。

## 1. 定位：独立核验 ≠ 润色 ≠ 章末检查点

| 批次类型 | 视角 | 管什么 |
|---|---|---|
| 章末检查点（SKILL.md §3.3） | 写作者自查 | 五项收口（符号/衔接/数值/术语/遗留） |
| 润色批次（polish-workflow.md） | 写作者自改 | 语言质量（不动论证） |
| **独立核验批次（本文件）** | **干净会话旁观者** | **找错与登记，不直接改** |

独立核验的产出是**核验报告**（问题清单＋处置建议），修改仍由写作线按报告执行——核验者不越权改稿。

## 2. 干净会话操作规程

1. **新开一个会话**——不带任何写作过程上下文，不粘贴旧对话（同 SKILL.md §5 的会话纪律）；
2. 只给它**核验任务书**（§4 模板填写后）＋书稿项目路径＋技能路径；
3. 核验者读材料 → 逐项核验 → 写报告；**禁止**顺手改稿、补写、重排（发现问题只登记，不动手）；
4. 报告交回写作线与作者，处置意见由作者裁定。

要点：独立性来自「无写作上下文」——核验者没有写过这些内容，没有「我当时想表达什么」的记忆可用，只能看文字本身是否成立。多窗口并行时窗口命名建议 `核验-第X章`（session-management.md §3）。

## 3. 引用语义错配核验（核心清单）

脚本能查「编号连续、题录核对」，查不了「这条引用是否支持这个论断」——这是机器盲区，靠本流程补位。对范围内每条 [n] 引用：

1. 读正文该引用处的**论断**（加粗观点句或数据句）；
2. 回到语料读该文献**实际讨论的内容**（研究对象、条件、结论）；
3. 判定匹配度，匹配不上的写入**错配清单**，每条四字段：

```
编号 | 正文论断 | 原文实际支持 | 处置建议
```

典型错配形态（提示，不穷尽）：

- **范围放大**：文献只在某条件下成立，正文写成普遍结论；
- **对象偷换**：文献研究的是 A 对象，正文用于 B 对象；
- **数值漂移**：文献值有区间或前提，正文取极值或去前提；
- **因果升级**：文献报告相关性，正文写成因果；
- **时态错位**：文献的展望/推测被引成已验证结论。

处置建议三类：**改论断**（加限定、降级语态）／**换文献**（语料内重选）／**删引用**（无据可依处按红线标注"此处需补充文献支撑"）。核验者只登记不改稿。

**拦截层记录**：核验报告对每个发现的问题标注它是在哪一层被拦截（或漏网）的——①Agent 写作时拒绝/标注；②本核验批次检出；③（事后）作者发现。此口径用于质量复盘：写作线读报告后，把高发错配形态补进 `references/batch-workflow.md` §6 坑清单，让同类问题在写作层就被拦截。

## 4. 核验任务书模板

```markdown
【核验任务书】
- 范围：第X章 Y.Z 节（文件清单逐个列出）
- 材料：项目根目录路径；语料接入方式（台账 §1 登记）
- 核验清单（按需勾选）：
  [ ] 引用语义错配（verification-batch.md §3，逐条 [n]）
  [ ] 术语/符号一致性巡检（polish-workflow.md §5b CONS 模板）
  [ ] 关键数值与台账登记逐条对照
  [ ] 图表证据卡与正文陈述一致
  [ ] 结论语态（推测/已验证是否分清）
- 输出：核验报告（问题清单＋处置建议＋拦截层标注），写到 <指定路径>
- 禁止：改稿、补写、重排、越出任务书范围的"顺手优化"
```

## 5. 任务回执格式

任务｜范围｜执行状态｜发现问题（按类型计数）｜错配清单（如有）｜风险与待核实项｜建议下一步。

## 6. 何时触发

- **章末检查点之后**（推荐：核心章节、引用密集章节）；
- **作者点单**（「独立核验第X章」）；
- **全书收尾前**（各章核验报告汇总复核，作为全书终检的证据输入）。

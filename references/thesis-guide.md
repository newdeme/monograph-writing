# 学位论文写作专项指南（创新点 · 成果关系 · 盲审隐名 · 查重）

> SKILL.md §0.1「文体与学科声明」的学位论文分册。适用 `genre: thesis`（博士/硕士学位论文）。核心问题只有一个：**学位论文里大量内容是作者本人未发表的成果**——它们是论文的贡献本体，不是文献。本指南把由此衍生的四件事做成可执行的登记表与规程。

## 1. 学位论文与专著的关键差别

| 维度 | 学术专著/教材/技术书 | 学位论文 |
|---|---|---|
| 参考文献主体 | 基本为已发表成果（他人＋本人已发表） | 同左，**另有大量本人未发表内容（试验/数据/推导）** |
| 成果归属表述 | 体系性优先，作者成果融于全书论证 | **创新点必须显性声明**，评审按创新点打分 |
| 评审方式 | 出版评审/社审 | 盲审（多校要求隐名）＋查重 |
| 自引规则 | 注明关系即可 | 注明关系＋隐名版特殊处理＋查重口径 |

落笔规则**全部沿用通用机制**（成果四分类见 `references/evidence-corpus.md`）：A 类正常引、B 类注明关系、C-数据冻结后可 [DS/OL]、C-草稿永不入文献表。本指南只做学位论文特有的增量。

**两个设计原则**：①论文按「**抽查**」设计——盲审专家通常不通读全文，多走"摘要 → 创新点声明 → 抽一章验证证据链"的路径（此为分析性推断，尚非经写作实践验证的定论），因此**每章必须能独立经受抽查**：章首交代本章位置、章内证据链自足、章末小结可独立成立；②专著按「**查阅**」设计——读者当参考书翻阅，每章要能独立检索、交叉引用完整。这也解释了二者**不可简单互改**：论文抽掉资格证明骨架后剩不下体系；专著塞入创新点声明会破坏体系叙事。

## 2. 创新点登记表（初始化后建立，随批次维护）

新建 `00_管理文件/创新点与成果声明.md`（init 生成模板，`genre: thesis` 时）：

```markdown
# 创新点与成果声明｜《书名》

## 1. 创新点登记表

| 编号 | 创新点（一句话判断句） | 支撑章节 | 对应成果（B 类） | 状态 |
|---|---|---|---|---|
| 创1 | （例）提出了…方法，在…条件下优于… | 第3章 3.2、3.3 | 已发表[n]/拟投稿/未发表 | 已验证/在研 |

## 2. 攻读期间成果与章节关系清单（B 类关系注明台账）

| 成果 | 与章节关系 | 关系注明句（写进正文的首现处） | 隐名版处理 |
|---|---|---|---|
| 论文一（题录） | 第4章基于其扩展 | "本章基于作者已发表工作[n]扩展：…" | 去名化保留/移除（按本校规定） |
```

维护规则：每批次收尾更新；答辩前逐条核对"每个创新点至少有一个支撑章节、每个支撑章节至少服务一个创新点"；**创新点表述必须是可论证的判断句**（同论点树标准），不得写成方法罗列。

**创新点六要素**（登记表每行逐项自查）：明确问题 / 与已有工作的差异 / 支撑章节 / 定量实验 / 消融实验 / 失败案例与适用边界。"设计了一个模块""构建了一个框架"只是工作描述；"提出 X 机制，通过 Y 途径，在 Z 条件下优于 W"才是可验证的判断句。

**三处对称（刚性检查）**：绪论的研究问题、贡献章节的声明、结论的回应**逐条对称**——这是论文区别于专著的最刚性核对项，答辩前逐条过一遍。

**贡献不写得比证据大**：明确限定任务、数据集、场景与实验条件——方法只在一个数据集上验证不得宣称普遍适用；指标提升有限不得上升为"解决了某领域问题"。审慎的边界声明不会削弱论文，反而体现研究成熟度。

**实验论证七问**（理工实验学科预设，其他学科按学科声明取舍；实验章写作与自查用）：

| 论证目标 | 检查问题 |
|---|---|
| 有效性 | 是否优于合理且充分的 baseline？ |
| 归因 | 提升是否来自所提模块（消融实验）？ |
| 稳健性 | 对不同问题类型是否都有效？ |
| 泛化性 | 是否只在某一数据集或某一 backbone 上成立？ |
| 公平性 | 参数量、训练成本是否造成不公平比较？ |
| 证据质量 | 证据本身是否更准，还是仅指标提高？ |
| 适用边界 | 失败条件是什么？ |

原则：论文可以接受结果不完美，**不能接受论证链断裂**。

## 3. B 类关系注明的三种句式（正文首现处或章首）

1. **扩展型**："本章在作者已发表工作 [n] 的基础上扩展了……（新增部分为……）"——最常见，扩展点要写实。
2. **改写型**："本节内容改写自作者已发表工作 [n]，并按本书体例重新组织。"
3. **并列声明型**（章末或前言统一声明）："本书第 X、Y 章内容已分别发表于 [n][m]，学位论文文本在此基础上形成。"适用于多章对应多篇已发表论文的"论文集式"学位论文。

**禁止**：把已发表论文内容整章搬入而全文不注明关系——查重系统虽有"去除本人已发表文献复制比"口径，但关系不注明在盲审与学术规范层面构成自我抄袭争议。

## 4. 盲审隐名版导出规程（blind_review: true 时）

各校规定不一，**以本校研究生院最新文件为准**；常见两种主流做法，导出前与作者确认选哪种：

1. **去名化保留**（成果目录保留，隐去姓名）：创新成果目录按参考文献格式列出，但作者只署"第 X 作者/第 X 完成人"，不写姓名与单位。
2. **整体移除**：送审版删除"攻读期间发表成果"目录及一切可识别身份的表述。

隐名版导出 checklist（AI 助手逐项执行并出核对单）：

- [ ] **格式手册时效核验**：打开本校研究生院**现行**学位论文格式手册/撰写规范，登记「版本（或发文号）＋获取渠道＋核查日期」进台账 §5——格式要求年年微调，**凭记忆写格式＝引旧版国标同型错误**（batch-workflow 坑清单第 15 条）；页边距、字号行距、图表编号体例、参考文献格式一律以现行手册为准，不以本技能默认样式为准
- [ ] 封面/题名页/独创性声明：隐去作者与导师姓名（按本校模板）
- [ ] 致谢：整节移除（致谢是身份识别重灾区）
- [ ] 基金/项目编号：隐去或按校规保留（项目编号可反查主持人，须确认）
- [ ] B 类自引条目：按选定做法去名化（"作者已发表工作"替代姓名）或移除
- [ ] 创新点登记表第 2 节"隐名版处理"列逐条执行
- [ ] 正文"作者已发表工作 [n] 处的 [n] 指向被改写条目后，**引用编号重排并复跑 validate**（隐名版单独一份目录，不动常规版）
- [ ] 导出后全文搜索作者姓名/导师姓名/学号，确认零残留

## 5. 查重与重复发表口径（写作期就要管，不是送审才管）

1. **已发表内容进论文**：注明关系（§3 句式）后属正常时序，各校查重普遍剔除"本人已发表文献复制比"；但重复率上限按本校规定执行，整章搬用仍可能超线——大段复用前先与作者评估占比。
2. **未发表草稿双向风险**：C-草稿若同时在投，论文入库后会与其发表版互撞。规则：**同一素材的文字版只能有一个正式归宿**；在投稿件作为素材重写进论文时，在台账 §5 登记"该稿拟投 XX，论文第 X 章与其同源"，送审前与作者、导师确认处理（撤稿/改写幅度/引用关系）。
3. **C-数据冻结的价值**：冻结快照（台账 §4b）是数据在写作期的"定版证明"——将来任何版本争议（导师/合作者/审稿人质疑数据改动）都可回溯到冻结时刻的 SHA256。
4. **可复现性记录**（理工实验章配套，作为论文内容的一部分而非附录装饰）：数据（数据集版本与划分、预处理）、训练（随机种子、模型/backbone、optimizer/lr/scheduler、batch size/epoch/精度）、环境（框架、CUDA、GPU 型号）、评测（评价脚本与指标口径、checkpoint 选择规则）、代码（commit hash）——逐项随章登记；数据与代码的版本证据即台账 §4b 冻结记录。
5. **多人协作边界（学术伦理红线）**：学位论文不允许协作代写。本技能的接力机制在学位论文项目中仅限同一作者的多会话/多设备续作与导师批注意见的登记流转；章节内容必须由学位申请人本人完成。合著成果按 B 类规则引用并注明关系（第几作者写实），不得以「合作写作」名义混入他人代写的章节文本。

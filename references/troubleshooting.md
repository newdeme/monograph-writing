# 报错对照速查（脚本输出 → 原因 → 修复）

> 脚本报错看不懂时先查本表：按「症状关键词」对号入座。通用兜底：**把脚本的完整输出原样复制给你的 AI 助手，说"帮我修好它"**——四条脚本全部支持由 AI 代跑代修，人不必读懂任何报错。

## 1. `validate_manuscript.py`

1. **症状：`[配置文件语法错误] … 第 N 行第 M 列附近 JSON 语法有误`**
   出了什么：《书稿配置.json》第 N 行附近 JSON 语法坏了（最常见：上一行行尾漏逗号；其次：字符串两端误用中文引号、多了逗号或换行）。
   怎么改：①用编辑器打开该文件跳到第 N 行，补上逗号（或把中文引号改回英文 `"`）；②自检：终端跑 `python3 -m json.tool "00_管理文件/书稿配置.json"`——无输出即合法；③重跑校验脚本。
   预防：手动改配置一次只改一处，改完立刻跑第②步自检。
   （旧版本此场景会打印整屏英文 `json.decoder.JSONDecodeError …` traceback——含义与本条相同。）

2. **症状：`[ERROR] 某文件.md（编码错误）… 不是 UTF-8 编码`**
   出了什么：该书稿文件不是 UTF-8 编码（常见于从网页/微信/旧 Word 直接粘贴另存的文件）。
   怎么改：用编辑器打开该文件 →「另存为」时选 UTF-8 编码 → 重跑校验。
   预防：所有书稿文件统一用 UTF-8 保存；不确定时先跑一次校验脚本扫编码。

3. **症状：`[ERROR] 某文件.md … 缺少必需章节标题: ## 一、写作准备`（或 `引用编号非按首次出现顺序递增`、`表编号跳号`、`字数 … 远低于目标` 等）**
   这些是**书稿内容问题**而非环境问题，正是校验脚本的本职。逐条含义与修复手法见 `references/batch-workflow.md` §3 与 §6「常见坑清单」；修完复跑至「全部通过 ✅」。

4. **症状：`[目录不存在] …01_书稿`**
   出了什么：不在项目根目录运行，或书稿目录还没建。
   怎么改：在项目根目录运行；或在别处运行时加 `--root <项目根目录>`。

5. **症状：`[WARN] 素材漂移：<文件> 与台账 §4b 冻结时不一致`**
   出了什么：某份已冻结登记（台账 §4b）的数据素材，其原文件在冻结之后被改动过——依赖它的章节用的是"旧版数据"，数字可能已对不上。
   怎么改：①核对差异是否影响已写章节的结论；②数据确要更新 → 把新版再次冻结（快照复制到 `02_语料/定稿数据/`，台账 §4b 新增一行登记），依赖章节按需修订；③属误改 → 从 `定稿数据/` 快照恢复原文件。处理后复跑校验。
   预防：改动 02_语料/ 里的数据文件前，先查台账 §4b 是否已登记冻结。

6. **症状：`[WARN] C-数据证据未冻结：<文件> 使用了未冻结登记的作者数据`**
   出了什么：正文以"作者试验数据"方式使用了未在台账 §4b 冻结登记的数据素材——数据还会变，写死的数值将来可能失据。
   怎么改：数据已定稿 → 冻结登记（快照＋§4b 一行）后 WARN 消除；数据仍在迭代 → 属正常在研状态，把 WARN 连同理由记入台账 §6 即可收批；确需著录进参考文献表 → 冻结后按 [DS/OL] 著录（规则见 `references/evidence-corpus.md` §8）。

## 2. `init_project.py`

7. **症状：`[参数错误] … 是一个文件，而项目根目录应是一个文件夹`**
   出了什么：把《专著目录.md》的**文件路径**当成了项目根目录传入（历史版本此处会打印 `NotADirectoryError` 英文 traceback）。
   怎么改：第一个参数改传项目根目录（一个文件夹），目录文件用 `--catalog` 指定：
   `python3 init_project.py <项目根目录> --catalog <目录.md> --title "书名"`。

8. **症状：`[未找到目录]`**
   出了什么：项目根目录及其 `00_管理文件/` 下都没有《专著目录.md》。
   怎么改：把目录文件放到位，或用 `--catalog` 指定路径；还没想好目录时加 `--sample` 生成示例目录照着改。

9. **症状：`[目录无法解析] … 未检出任何 '## 第X章 …' 行`**
   出了什么：目录文件格式不符（章行须为 `## 第X章 标题`，节行 `**Y.Z 节标题**`，小节行 `- X.Y.Z 小节标题`）。
   怎么改：按 SKILL.md §2 的格式三行样式改写目录后重跑。

10. **症状：`[拒绝覆盖] …写作进度台账.md 已存在`**
   出了什么：项目此前初始化过，脚本防止误覆盖。
   怎么改：确要重来才加 `--force`（只覆盖台账类文件，不动 01_书稿/）。

## 3. `generate_figures.py`

11. **症状：`[缺依赖] 生成数据图需要安装 matplotlib`**
    怎么改：终端执行 `pip3 install matplotlib` 后重跑（或让 AI 用 `uv run --with matplotlib` 代跑）。

12. **症状：`[跳过] 图X-Y：数据漂移——…当前（xxxx）与登记（yyyy）不一致`**
    出了什么：该图登记的数据文件在登记之后被改动过，图与数据已对不上。
    怎么改：数据确已更新 → 用新校验和更新台账 §3b 该行后重跑；误改 → 从 `02_语料/定稿数据/` 快照恢复。相关联的章节须复核。
    （`[跳过] 图X-Y：…已存在` 属覆盖保护——覆盖需走变更单或显式 `--force`。）

## 4. `generate_stripped_version.py`

13. **症状：`[跳过] 某文件: 文件不是 UTF-8 编码`（或 `类型A结构不完整：正文或参考文献标题缺失`）**
   出了什么：该文件编码不对或不是标准三段式（缺 `## 二、正文` / `## 参考文献` 标题）。
   怎么改：按提示修复对应文件（转码/补标题）后重跑；剥离版每次整体重建，重跑安全。

14. **症状：`未生成任何剥离版：N 篇文件异常`（退出码 1）**
    出了什么：本批全部文件异常，一条都没剥成——不要去跑 Word 合并。
    怎么改：按上方各条 `[跳过]` 原因修复后重跑。

## 5. `merge_to_word.py`

15. **症状：`[缺依赖] 生成 Word 需要安装 python-docx`**
    怎么改：终端执行 `pip3 install python-docx` 后重跑（或把这句交给 AI 助手代跑）。

16. **症状：`[目录缺失]` / `[剥离版缺失]`**
    出了什么：缺《专著目录.md》或还没生成剥离版。
    怎么改：先跑 `generate_stripped_version.py` 再回来合并。

17. **症状：`注意：N 个单元因文件缺失/结构异常未并入（Word 稿仍已生成…）`**
    出了什么：个别剥离文件结构异常（如缺 `## 参考文献` 分隔）或定位不到，**已自动跳过并继续**，Word 稿其余部分完好，缺口处有灰色标注。
    怎么改：按列出的清单逐个修复（多为补标题或改回标准文件名）后整体重跑——合并稿每次整体重建，补齐即可。

18. **症状：`编号回退匹配: N 条`**
    说明：目录标题与实际文件名不完全一致（含文件系统非法字符，或名称漂移），脚本已按编号前缀自动匹配成功，Word 标题仍用目录原文。属提示非错误；想消除漂移，把目录名改回与《专著目录》逐字一致。

19. **症状：`FileNotFoundError … 节目录无法定位：期望「Y.Z …」`**
    出了什么：某节的目录夹名与《专著目录》差异过大，连编号前缀也匹配不上（如目录夹名编号都写错）。
    怎么改：按报错里"实际有"的清单，把目录夹名改回与《专著目录》逐字一致（文件名漂移是历史最高发的坑，见 `references/batch-workflow.md` §6 第 8 条）。

## 6. 通用原则

- 四条脚本都遵循同一报错格式：**[出了什么] → 常见原因 → 怎么改**；照"怎么改"一步做即可，做完重跑。
- 任何拿不准的输出：整段复制给 AI 助手说「帮我修好它并告诉我以后怎么避免」。
- 一切以脚本复跑结果为准：「全部通过 ✅」或"生成完成"出现前，不要认为收尾。
- 「把自己的数据/草稿引成文献」与盲审隐名版自引处理不是脚本报错，而是学术规范问题：见 `references/evidence-corpus.md` §8（成果四分类与学科差异）与 `references/thesis-guide.md` §4（盲审隐名版导出规程）。
